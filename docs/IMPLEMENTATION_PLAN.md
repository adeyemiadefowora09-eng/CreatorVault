# CreatorVault — Official Architecture & Implementation Plan

## 1. System Architecture

The platform uses a decoupled frontend-backend architecture:

- **Frontend**: Next.js 15 (App Router) + Tailwind CSS v4 + React Hook Form + Zustand
- **Backend**: Node.js + Express.js + TypeScript
- **Database**: PostgreSQL (via Prisma ORM)
- **Payments**: Payaza API
- **AI Engine**: OpenAI (gpt-4o) — **AI Deal Guardian** & Trust Scoring

### Domain Modules (Backend)
1. **Auth**: JWT-based authentication (Access & Refresh tokens).
2. **Users**: Profiles for Creators and Brands, dynamic Trust Score engine.
3. **Deals**: Core deal lifecycle (`DRAFT` → `PROPOSED` → `ACTIVE` → `COMPLETED`).
4. **Milestones**: Deliverable tracking and payment triggers.
5. **Contracts & AI (AI Deal Guardian)**: File uploads, digital signing, and OpenAI-powered contract risk analysis.
6. **Payments (Payaza)**: Payment initialization, verification, and webhook handling.
7. **Reviews**: Post-deal ratings and feedback.
8. **Disputes**: Conflict resolution and escalation.
9. **Notifications**: In-app user alerts.

---

## 2. Database Schema (Prisma)

The core entities revolve around the **Deal**.

- **User**: Base account (Creator or Brand).
  - Has one `CreatorProfile` or `BrandProfile`.
  - Links to `TrustScore` (tracks dynamic rating & score history).
- **Deal**: The agreement between a Creator and Brand.
  - Contains multiple `Milestones`.
  - Links to a single `Contract`.
- **Contract**: The legal document.
  - Links to `ContractAnalysis` (Generated by AI Deal Guardian).
- **Payment**: Financial transaction tied to a Deal/Milestone (Provider: Payaza).
- **Review**: Ratings left by parties on completed deals.
- **Dispute**: Raised when parties disagree on deal execution.

---

## 3. Third-Party & AI Integrations

### Payaza (Payments)
- **Initialization**: Brands initialize payments for approved milestones. The backend calls `POST /api/v1/applications/initialize` on Payaza and returns a checkout URL.
- **Verification**: The frontend redirects to `GET /payments/verify/:reference` which confirms the transaction.
- **Webhooks**: Async updates via `charge.success` events to safely mark milestones as `PAID`.

### AI Deal Guardian (Contract Risk Analysis)
- **Prompting**: Contracts are sent to `gpt-4o` with a strict JSON structure request.
- **Output**: Returns a Risk Level (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`), an overall safety score, flagged clauses (with explanations), and actionable recommendations.

### Trust Score Engine
- **Base Score**: Starts at 50 points.
- **Updates**: Triggered automatically on deal completion, review submission, dispute resolution, or contract risk detection.
- **Calculation Rules**:
  - Completed Deal (No Dispute): +10 pts
  - High Review (>4.5 stars): +5 pts
  - Timely Milestone Delivery: +5 pts
  - Open/Lost Dispute: -15 pts
  - AI Deal Guardian CRITICAL Flag: -10 pts
  - Score Boundary: 0 to 100
